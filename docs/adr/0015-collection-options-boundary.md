# ADR-0015：収集条件の設定と有効な値を区別する

## 状態と対象

採用。[Issue #60](https://github.com/shigaresso/player-lens/issues/60) に対応する。ADR-0014 の状態生成時の条件正規化を、条件の生成 API に移す。既定値・上限・外部 JSON・MCP の拒否順序を維持する。

## 背景と比較

同じ公開 struct が未検証の入力と検証済みの値を兼ね、CLI/MCP の正規化後に収集状態でも同じ処理を繰り返していた。単に再検査を削除すると、有効性の前提が型から分からず、生成後の書き換えも防げない。

収集条件だけを対象に、公開フィールドの CollectionOptionsConfig と、非公開の設定を持つ CollectionOptions を分ける。他のドメイン型や PageOptions の入力境界は変更しない。互換エイリアスや委譲だけのサービスを残さず、参照元を移行する。

## 決定

NewCollectionOptions は Config の既定値・評価種別・言語・件数・ページ数を検査・正規化する。不正ならゼロ値と ErrInvalidArgument を保持するエラーを返し、呼び出し側がエラーを処理する。成功した値のフィールドは外側から書き換えられない。Config は設定のコピーを返す。

CollectionOptions のゼロ値は従来どおり有効な既定条件を表す。生成 API の明示的な既定条件も同じゼロ値へ揃える。外部から作成できる値はゼロ値か生成値であり、利用側は未初期化チェックや全項目の再検査を必要としない。ゼロ値から設定を取り出す処理は固定の既定値を返し、正規化を繰り返さない。

CLI と MCP は未検証の入力を Config に変換して生成 API を呼ぶ。MCP の20件/3ページの既定値、100件/5ページの上限と正確な JSON キー検査は入口に残す。不正入力の拒否は利用枠の確保前とし、生成エラーを無視して既定値を実行しない。

収集状態と application は CollectionOptions を受け取る。状態生成は App ID の条件を担当し、Config のコピーを結果へ保持する。Collection.Options は表示・保存用の Config とし、空の Collection の未指定値を自動的に既定値へ変えない。手作りの不正な結果に対する JSON 出力境界の拒否も維持する。

## 利点と制約

生成側と利用側の契約を区別し、有効な条件を受け取る処理から重複した検査を除ける。Go の呼び出し元は設定の生成とスナップショットの型を更新する必要がある。無効な条件は操作側のテストでは表現できなくなるため、その拒否は生成 API と CLI/MCP の入口へ引き継ぐ。

ゼロ値も有効なので、生成エラー時の戻り値だけでは失敗と区別できない。呼び出し側は戻りエラーを処理する。これは未初期化を拒否する MCP の Limits とは異なる、既存の収集条件のゼロ値契約を維持する選択である。
