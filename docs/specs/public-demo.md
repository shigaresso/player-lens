# 公開デモ仕様

## 目的と状態

PlayerLens をポートフォリオとして公開し、レビューから根拠付きレポートを作る目的、成果物、実装・検証状況を閲覧者が理解できるようにする。

Issue #148 でプロンプト作成画面を実装した。ローカル表示と操作を確認し、Render への配置・公開 URL での表示は未確認とする。ブラウザからのレビュー取得・分析・保存 UI は未導入である。Issue #31 の作業中にユーザー配置の公開 MCP の基本 HTTP 通信を確認した。Issue #138 でユーザーから OpenAI 側（ChatGPT App／Codex）でのローカル・Render の MCP 利用は実機確認済みという報告を受けた。Claude Code のみ実機未確認であり、検証済み digest の配置は別途未確認とする。MCP は認証なしで収集を提供する。公開するデータ・操作の範囲、バックエンド分析の利用コード・期限・回数、公開構成に必要な追加制御は実装前に対応 Issue で決める。Issue #27 では [MCP の1プロセスの利用制限](mcp-usage-limits.md) を導入した。公開構成の共有予算・配置の代わりにはしない。

## 公開範囲と制御

- 閲覧できる保存済み成果物と、新規調査を実行できる範囲を明示する。
- MCP のレビュー収集は認証なしとし、[公開 MCP 仕様](mcp-public-access.md) の許可 Host と実行制限を適用する。バックエンドの LLM 分析は別途、利用コード・利用期限・残り回数の契約を Issue で決定・検証する。
- 新規調査には [データ・調査仕様](data-and-research.md) の件数・時間・費用などの上限を適用する。
- UI を導入する場合は、各表示状態と期待結果を対応する仕様・Issue に記録する。テンプレートの検査とブラウザでの動作確認を区別する。
- 実装済み・確認済みの機能と、構想・未実装の機能を区別して公開する。

## プロンプト作成画面（Issue #148）

GET/HEAD `/` で日本語の画面を提供する。画面は文章を作るだけで、Steam／MCP／LLM の呼び出し・利用枠の消費・保存を行わない。入力と出力は DOM 内でのみ扱い、サーバーへ送信したりログへ記録したりしない。依頼文作成機能を `internal/reviewprompt` にまとめ、Controller は `adapter/handler/prompt_builder.go`、Go の描画と HTML・CSS・JavaScript は配下の `page` に置く。生成・組み立てとルーティング登録は `cmd/server` が担当する。Go の embed に HTML・CSS・JavaScript を含め、外部資産へ依存しない。CSP で固定資産のハッシュだけを許可し、通信とフォーム送信を禁止する。

| 入力・操作 | 契約 |
| --- | --- |
| Steam 商品 URL | `https://store.steampowered.com/app/<数字>/` を解析する。作品名、query、fragment は無視できる。別ホスト・別スキーム・認証情報・既定以外のポート・1〜4294967295 に収まらない ID は拒否する。作品の存在確認はしない |
| 評価 | すべて・おすすめ・非おすすめ。Steam のおすすめフラグであり、本文の意味分類ではない |
| 言語 | 日本語・英語・全言語。画面の初期選択は日本語で、MCP の省略時の英語とは区別する |
| 件数・ページ | MCP の入力 schema の上限・既定値を共有する。最大収集件数20、1ページ100件、最大3ページを初期表示し、0による省略指定は使わない。指定は取得件数の保証ではない |
| 接続名 | Render／ローカルの既定名か独自名。独自名は Unicode の文字・数字・`_`・`-` の1〜64文字だけを許可する。MCP 登録は別途必要 |
| 生成 | 6つの引数と1回だけの実行、`analysis_guide`、レビュー ID、意見と解釈・不足の区別、追加取得・レビュー内の指示の禁止、ツール不在時の中止を案内する |
| 入力変更・失敗 | 古い依頼文を消してコピーを無効化する。不正項目に説明とフォーカスを与える。コピー失敗時は文章を選択して手動コピーを案内する |
| JavaScript 無効 | 必要であることを表示し、生成を無効にする |

URL・条件の変換とコピー処理は Node.js の通常テスト、HTML と schema・CSP は Go の通常テスト、実 HTTP は integration タグ付きテストと本番イメージで検証する。実ブラウザの生成・変更・不正入力・コピー・狭い画面の確認は、これらの自動検査と区別して [検証記録](../worklogs/148-prompt-builder.md) と Issue #148 に記録する。クライアント AI の分析内容・ツール選択の遵守を画面のテスト成功だけで保証しない。

## プロンプト作成画面の応答ログ（Issue #150）

GET/HEAD `/` の handler が通常 return するときに、`prompt_page.completed` を1回記録する。ブラウザでの表示・依頼文生成・コピーの成功を表すものではなく、HTTP の応答処理を観測する。root の405・未定義404・他経路の記録は含めない。panic は回復せず伝播し、専用の完了ログも追加しない。

起動側の slog.Logger と時計を生成関数に渡す。依存は有効な非 nil・並行利用可能なものとし、生成・登録時には計測・ログ出力を行わない。Controller が時刻と結果を取得し、`handler/page.Serve` が標準 ServeContent の実際のステータスと書き込み失敗を観測する。ログ項目・レベル・安全な分類は `handler/logging.PromptPage` が担当する。固定の `/` は handler.PromptPath を登録とログで共有する。

| 項目 | 契約 |
| --- | --- |
| event | prompt_page.completed |
| http.route | 固定の `/`。query を含めない |
| http.request.method | GET／HEAD |
| http.response.status_code | ServeContent が選んだ実際の値。200・206・304・412・416などを区別する |
| duration_ms | Controller 開始から応答処理終了までの数値、ミリ秒。ログ出力時間とクライアント受信・表示は含まない |
| outcome | success／rejected／response_failed／write_failed |
| error_code・cause_kind | 書き込み失敗時だけ response_write_failed と安全な原因分類を付ける |

200/206/304などは INFO/success、4xx は WARN/rejected、5xx は ERROR/response_failed とする。書き込み失敗はステータスによらず ERROR/write_failed を優先し、キャンセル・期限超過・切断・通信タイムアウト・unknown の順に分類する。ラップした原因も errors.Is/As で判断する。短い書き込みは失敗として観測する。部分応答・条件付き要求・既存の書き込み結果は変更せず、失敗時に再書き込みしない。

時刻・level・msg と service.name は既存 slog 構成を使い、msg は「プロンプト作成画面の応答を処理した」に固定する。受信 query・ヘッダー・IP・User-Agent・入力・生成文・任意のエラー全文を属性に追加しない。ログ出力先の通常の Write エラーでは応答・元の失敗を変更しない。通常テストは io.Discard、内容の検証はメモリ上の記録先を明示し、ターミナルへ出力しない。

リクエスト context をそのまま LogAttrs に渡し、キャンセル済みでも置き換えない。将来の OTel 接続経路を保持するものであり、仮の trace ID・SDK・保存基盤は追加しない。既存 JSON/stderr を使い、新しいファイル・DB・goroutine は設けない。保持・検索・送信成功は配置側の別の責務である。

検証は Go の単体テスト、実 HTTP／実バイナリの stderr、同じ本番イメージに分ける。[ADR-0022](../adr/0022-prompt-page-structured-logging.md) に判断を記録し、[作業記録](../worklogs/150-prompt-page-logging.md) に Red/Green と実行結果を残す。

## README の要件

アプリケーションの README に、目的、デモ URL、サンプルレポート、構成、起動・検証方法、現在の制約を記載する。URL やコマンドが未導入の場合は未導入と記載し、架空の URL や実施していない検証結果を載せない。

Codex から MCP を利用する手順は、ローカルサーバーの起動・実ポートでの登録と、Render の公開 URL の登録を分けて記載する。ChatGPT App の日本語 UI に合わせて画面への経路を説明し、接続名、Streamable HTTP、設定後の再起動・ツール確認、接続先を指定した少量取得と分析のチャット例を含める。取得・分析の担当、根拠 ID、外部データの扱い、部分失敗や利用制限の確認を案内し、HTTP 診断の成功を実クライアントでの分析確認と混同しない。

MCP の登録手順には利用するクライアントの公式資料をリンクし、実機で再現確認していない場合は登録手順の近くに明記する。文書・help の照合、ユーザーの画面情報、過去の実接続確認を区別し、文書の検査だけで登録・接続・分析を確認済みと扱わない。

チャット例に含めるツール入力には、項目の意味、受け付ける値、必須か省略可能か、省略時の既定値を併記する。Steam 由来の型・上限とアプリケーション独自の制約・既定値を区別する。1ページの要求件数、収集合計の上限、ページ数の上限を区別し、上限の指定を取得件数の保証と扱わない。

## 期待結果と検証への対応

以下は公開機能を導入する際の完了条件であり、検証済みの動作ではない。

| 状況 | 期待結果 | 導入時の検証 |
| --- | --- | --- |
| 保存済みレポートを閲覧した | 収集条件と限界を含む、公開対象の成果物を表示する | レポートの契約テストとブラウザ確認 |
| 新規調査を実行しようとした | 公開範囲・必要な利用コード・期限・上限の契約に従って受け付けるか拒否する | 許可・拒否の境界値と Web・MCP の結合テスト |
| 調査が失敗または未完了になった | 成功済みの成果物と混同しない状態を表示する | 状態遷移のテストと表示確認 |
| README から起動・検証した | 掲載した実行手順で、導入済みの構成を再現できる | 手順の実行と結果の記録 |
