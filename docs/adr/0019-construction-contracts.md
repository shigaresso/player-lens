# ADR-0019：生成・更新の境界と依存の存在を静的検査で支える

## 状態と対象

採用。Issue #105 で、Limits・HTTPConfig・CollectionState の生成・更新と、NewHandler・CollectReviews の依存の契約に適用する。導入・実行結果は作業記録へ残し、方針の採用だけで検査済みとは扱わない。ADR-0008・0009・0014 の利用側の存在確認に関する記述を部分置換する。

## 背景と比較

生成側で有効な値を作った後、利用側でも依存の nil や設定のゼロ値を拒否していた。有効な依存・設定を渡す責務を生成・組み立て側へ集め、利用側はその契約を信頼する。これは任意の Go 呼び出しを安全にする変更ではなく、このリポジトリで守る API の事前条件である。

- 存在確認を各利用箇所へ置く案は、保証の責務が分散するため採用しない。
- 文書・レビューだけで生成経路を管理する案に対し、型情報を使った検査で違反を早く拒否する構成を採用する。
- 全 struct・標準型のゼロ値を禁止する案は、入力用の値・有効な既定値・検索結果などと区別できないため採用しない。

## 決定

型の宣言に `//contractcheck:controlled` を付ける。対象は非公開フィールドを持つ struct とし、同名の別型や import の別名と混同せず、型別名にも同じ規則を適用する。対象の宣言ファイル内で生成と状態更新を行い、それ以外のファイルでは生成済みの値をコピー・受け渡しして利用する。外部テストを含めて解析し、テストファイル全体の除外はしない。

独自検査は直接の複合リテラル、未初期化宣言、new、埋め込み先の省略フィールド・配列・make による暗黙の未初期化値、定義ファイル外からのフィールド更新・内部へのアドレス取得・ポインター経由の値の置き換えを拒否する。更新メソッドは有効な状態から有効な状態へ遷移させ、CollectionState.AddPage の終了判断や部分結果の契約を維持する。内部参照をそのまま外へ返す記述も検査し、コピーの独立性は型のテストで確認する。

生成成功なら有効な値・存在する依存を返し、失敗を呼び出し元で処理する。NewHandler と CollectReviews の fetcher は NilAway の nonnil(fetcher) 注釈で必須の契約を明示する。SDK callback の中で遅延利用する依存も、呼び出し位置の非 nil 条件として検査する。Limits の失敗値は NewLimits の生成結果を伝播し、入力解析側に直接の Limits{} を残さない。解析失敗はゼロの LimitsConfig を返す既存契約を維持し、NewLimits の結果とともに元の解析エラーを返す。解析失敗の原因を検証エラーで置き換えない。

既存 errcheck のエラー破棄の検査を維持し、nilnil で曖昧な nil と成功の同時返却を検査する。部分結果とエラーの同時返却は正当な契約のため禁止しない。NilAway は関数・パッケージをまたぐ nil の流れの検査に使い、固定版を実コードと違反 fixture で評価する。構造体のフィールド更新を追う experimental-struct-init を有効にし、無名関数解析は既存テストでの誤検知を確認して有効にしない。GOFLAGS で integration を指定し、無効な -tags 互換フラグに依存しない。ツールは tools の独立モジュールで版と go.sum を固定し、検証用イメージのみに配置する。本番の依存・イメージへ含めない。

NewHandler は生成済みの fetcher・Limits・HTTPConfig、CollectReviews は有効な PageFetcher を受け取り、存在を再検査しない。未生成の依存・設定を直接渡す行為は呼び出し側の契約違反となり、従来の入力エラー返却を保証しない。外部入力、AppID、応答欠落、利用枠、終了状態、資源解放の判断は残す。ゼロ値が有効な CollectionOptions と ValidatedPortNumber の契約は維持する。

## 検証と限界

型と生成・更新位置の検査、生成・状態更新の契約テスト、危険な nil のフロー解析を組み合わせる。独自検査もツールの実行経路も、正常例・違反例と非破壊性をテストする。実アプリケーションの隔離コピーへ3型の直接生成と、NewHandler の nil・型付き nil、CollectReviews の nil を挿入し、対象の注釈や解析設定が失われた場合も検証が失敗することを確認する。pre-push と go-lint CI は同じ読み取り専用コマンドを実行する。

配置の検査だけで任意の業務不変条件を証明しない。条件付きの取得・error・bool の扱いとコピーの深さは、フロー解析とテスト・レビューでも確認する。reflection・unsafe・cgo や外部コードによる任意の書き換え、全 nil panic の排除、競合の不存在まで証明したとは扱わない。false positive・false negative がある解析を、完全な非 nil 型システムとして説明しない。
