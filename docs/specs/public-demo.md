# 公開デモ仕様

## 目的と状態

PlayerLens をポートフォリオとして公開し、レビューから根拠付きレポートを作る目的、成果物、実装・検証状況を閲覧者が理解できるようにする。

Web UI は未配置とする。Issue #31 の作業中にユーザー配置の公開 MCP の基本 HTTP 通信を確認したが、検証済み digest の配置と実 ChatGPT 接続は未確認とする。MCP は認証なしで収集を提供する。公開するデータ・操作の範囲、バックエンド分析の利用コード・期限・回数、公開構成に必要な追加制御は実装前に対応 Issue で決める。Issue #27 では [MCP の1プロセスの利用制限](mcp-usage-limits.md) を導入した。公開構成の共有予算・配置の代わりにはしない。

## 公開範囲と制御

- 閲覧できる保存済み成果物と、新規調査を実行できる範囲を明示する。
- MCP のレビュー収集は認証なしとし、[公開 MCP 仕様](mcp-public-access.md) の許可 Host と実行制限を適用する。バックエンドの LLM 分析は別途、利用コード・利用期限・残り回数の契約を Issue で決定・検証する。
- 新規調査には [データ・調査仕様](data-and-research.md) の件数・時間・費用などの上限を適用する。
- UI を導入する場合は、各表示状態と期待結果を対応する仕様・Issue に記録する。テンプレートの検査とブラウザでの動作確認を区別する。
- 実装済み・確認済みの機能と、構想・未実装の機能を区別して公開する。

## README の要件

アプリケーションの README に、目的、デモ URL、サンプルレポート、構成、起動・検証方法、現在の制約を記載する。URL やコマンドが未導入の場合は未導入と記載し、架空の URL や実施していない検証結果を載せない。

Codex から MCP を利用する手順は、ローカルサーバーの起動・実ポートでの登録と、Render の公開 URL の登録を分けて記載する。接続名、Streamable HTTP、設定後の再起動・ツール確認、接続先を指定した少量取得と分析のチャット例を含める。取得・分析の担当、根拠 ID、外部データの扱い、部分失敗や利用制限の確認を案内し、HTTP 診断の成功を実クライアントでの分析確認と混同しない。

## 期待結果と検証への対応

以下は公開機能を導入する際の完了条件であり、検証済みの動作ではない。

| 状況 | 期待結果 | 導入時の検証 |
| --- | --- | --- |
| 保存済みレポートを閲覧した | 収集条件と限界を含む、公開対象の成果物を表示する | レポートの契約テストとブラウザ確認 |
| 新規調査を実行しようとした | 公開範囲・必要な利用コード・期限・上限の契約に従って受け付けるか拒否する | 許可・拒否の境界値と Web・MCP の結合テスト |
| 調査が失敗または未完了になった | 成功済みの成果物と混同しない状態を表示する | 状態遷移のテストと表示確認 |
| README から起動・検証した | 掲載した実行手順で、導入済みの構成を再現できる | 手順の実行と結果の記録 |
