# Issue #107：生成・更新境界の全体適用と利用側の再検査の禁止

Issue: https://github.com/shigaresso/player-lens/issues/107

## 範囲と設計

ユーザーの指定により有効性を保証する型と必須依存へ適用し、DTOなどは理由を記録して対象外にした。本番の cmd・internal の型を controlled・dependency・data と理由に分類した。保証対象は13型で、個別の分類理由は各型の宣言に記載した。テスト専用型と検査モジュール自身の型は本番型の分類と区別し、テストからの対象型の直接構築・更新は検査する。

AppID・PageOptions・ReviewType は公開された未検証入力の表現として data に分類した。これらの型名だけで検査済みとは扱わず、既存の入力・正規化・状態生成時の検査は維持した。error・context・利用枠・終了・応答の状態判断も維持した。

CollectionOptions の既定条件を定義ファイルの DefaultCollectionOptions から返す API にした。ゼロ値の意味と外部入力の契約を維持し、外側の直接構築と失敗値の比較を生成結果・reflect の観測へ移行した。NewSteamFetcher は失敗時にも NewClient の戻り値をそのまま伝播する。

Protect と CollectAndSaveReviews は生成済みの必須依存の存在を再検査しない。Protect から NewHandler までの生成エラーがなくなるため error 戻り値と呼び出し元の到達しないエラー処理も削除した。不正な公開 URL は設定生成時に引き続き拒否する。仕様と旧 nil 入力拒否のテストをこの契約へ移行し、Host/Origin・通常取得・部分失敗・保存・解放の検証を維持した。

## Red・Green

- 型の分類：project オプションと分類検査が未実装であるため失敗した。実装後は未分類・対象外理由の欠落を拒否し、保証対象・依存・理由付きデータを許可した。
- 引数の再検査：必須引数の nil 比較・別名とクロージャ・検証メソッド、任意指定の理由と名前・不正な生成関数指定の診断欠落で Red を確認し、実装後に Green を確認した。
- 追加の迂回：switch の nil 分岐・自己代入後の比較・検証メソッド値の取得、パッケージ変数の callback と型付き nil の比較の診断欠落で Red を確認し、実装後に Green を確認した。
- 任意指定の限界：任意指定による保証対象値の再検査と、nil を許容しない型の任意指定が拒否されない Red を確認し、実装後に Green を確認した。
- 既定条件の生成：DefaultCollectionOptions が未実装のためコンパイル失敗した。実装後は既存の既定条件を返すことを確認した。
- 本番への適用では、定義ファイル外の失敗値の直接生成・残っていた利用側の存在確認を検出した。移行後のアプリケーション全体の自作検査が成功した。機械的な移行・規約・仕様には形式だけの Red を追加しなかった。

検査を有効にすると移行前のコードも拒否されるため、検査ルールと必要な全体移行を一つの変更単位として確定する。必須 pre-commit・commit-msg はローカルコミット時にも実行する。push・PR 作成・Issue の手動クローズは行わない。

## 残る保証範囲

利用側の再検査を拒否する検査は、構文・型情報・通常の変数代入をたどる規約検査である。任意の helper や reflection・unsafe・外部コードの意味、呼び出し側の非 nil のフローや error・bool の正しい分岐、全 nil panic の不存在までは証明しない。対象外の理由の妥当性、生成・更新内容の業務条件はレビューと契約テストで確認する。

GitHub CI・実 Steam・LLM・Render は未実行。coverage 閾値・分岐・mutation は未導入であり、Stryker を実行したとは記載しない。
