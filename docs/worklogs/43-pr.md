## 背景・目的

Steam の ID・時刻・API 列挙値を組み込み型だけで扱っていたため、値の意味と API との対応を追いにくかった。公式の項目名と数値型に基づく定義型を導入し、内部の評価種別を数値列挙型に統一した。文字列の解析・生成を入出力境界へ移し、取得・収集・保存・CLI・MCP の受け渡しに同じ型を使った。

## 変更内容

- AppID・TimestampCreated・TimestampUpdated を uint32、RecommendationID を uint64 の定義型にし、Review のフィールドと全呼び出し元を更新した。
- 評価種別を EUserReviewsReviewType（int32）に統一した。公式名の数値定数を定義元とし、ReviewTypeAll・ReviewTypePositive・ReviewTypeNegative も同じ型の定数とした。文字列の ReviewType と HTTP 内の steamReviewTypeCode を廃止した。
- CLI・MCP の文字列を ParseReviewType で解析し、JSON は FormatReviewType で文字列に戻した。未知の整数を正規化・送信・出力で拒否した。残る API 列挙値も公式名の EUserReviewsAppReviewsFilter・EUserReviewsPurchaseType（int32）で表した。
- 応答専用データから recommendationid を数値化し、0・最大値・先頭ゼロを受け付けた。欠落・null・空・不正構文・範囲超過を拒否し、正数条件と重複する正規表現を除いた。数値として同じ ID は重複排除し、最初の値と取得順を維持した。
- schema_version=1 と既存の JSON 項目名・型を維持した。ID は10進文字列で出力し、先頭ゼロは正規化した。評価種別のゼロ値は全評価なので、空の Collection の options.review_type は空文字から all の明示に変更した。
- 文字列・bool の独自型やアプリの制限値の型を追加せず、仕様・ADR-0012・探索記録と境界のテストを更新した。

## 検証

RecommendationID の型・変換、ページ解釈の型、ParseReviewType、FormatReviewType、内部の取得・収集条件の列挙型を契約ごとに先にテストした。未定義 API・未対応フィールド・旧型との不一致による Red を確認し、対応する実装後に同じテストの Green を確認した。型の機械的反映では形式上の Red を作らなかった。

数値変換原因、HTTP を通す重複排除、JSON の項目名・型と精度、CLI の HTTP/保存連携、実 SDK による MCP の成功・部分失敗、出力での未知列挙値の拒否とゼロ値の全評価表現のテストを一つずつ追加した。既存実装で Green だった契約は実装を変えず回帰テストとして保存した。
