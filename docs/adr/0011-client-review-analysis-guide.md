# ADR-0011：分析ガイドをレビュー収集結果に添付する

## 状態

採用。Issue #35 でクライアント側の分析を案内する方針を決定した。実装・検証の状態は作業記録に分ける。

## 背景と比較

良い点・悪い点の列挙から、具体的な仕組みが誰に、どの条件で、なぜ評価されるかを学びたい。ジャンルや固定分類を前提にせず、取得レビューから分類し、企画への採否は人間に残す。分析はクライアント AI が担当する既存方針を維持する。

- 文書だけでは、MCP 呼び出し時にガイドを受け取れない。コピー用の依頼としては併用する。
- MCP の prompts や resources は、追加の取得やクライアントの対応・選択に依存する。今回は追加機能を必要とせずレビューと同時に届ける。
- ガイドを収集結果へ添付すれば、既存の tools/call の構造化結果・JSON テキストで受け取れる。毎回の応答量とモデルの入力は増える。
- バックエンド LLM や分析結果の提出・検証は、費用・新しい操作・保存の責務が増えるため今回は選ばない。

## 決定

`analysis_guide` の version と instructions を MCP 結果へ追加する。単一の Markdown 本文を Go の embed で組み込み、実行環境のソースファイルに依存しない。ガイドの責務は MCP の案内とし、steam・CLI・保存形式へ混ぜない。具体的な入出力と失敗時の扱いは [分析仕様](../specs/review-analysis.md) に定める。

ガイドは、本文からの分類・複数意見の抽出・類似意見の統合・条件による賛否の比較・レビュー ID・意見と解釈の区別・複数作品の比較・選択肢と影響の提示を案内する。分析対象が不足する場合に断定せず、人間が採否を判断する。

正常と失敗で同じガイドを返し、二重化を含めて既存の128 KiBへ計上する。版のある独立フィールドとし Collection の schema_version=1 は維持する。追加フィールドを拒否する既存クライアントでは更新が必要になる。

## ブラウザでの依頼文作成（Issue #148）

トップページで商品 URL と選択条件から AI 向けの依頼文を作る。静的資産を Go に埋め込み、ブラウザ内の変換とコピーだけを行う。バックエンドの新しい UseCase・保存・MCP 通信は追加しない。MCP prompts のクライアント対応に依存させず、登録済み AI へ貼り付ける使い方を補助する。

入力上限と数値の既定値は MCP schema から共有し、画面の日本語という初期選択は別の表示方針として明示する。分析指針の本文は複製せず、収集結果の analysis_guide に従うよう依頼する。依頼文は AI の実行・遵守を保証せず、MCP の登録も代行しない。画面の契約は [公開デモ仕様](../specs/public-demo.md#プロンプト作成画面issue-148) に定める。

## 利点と制約

追加のツール呼び出し・Steam 通信・実行時ファイルを必要とせず、ガイドとレビューを一緒に渡せる。新しい外部依存や分析ジョブを作らずに方針を共有できる。

ガイドはクライアント AI への案内であり、最終回答の強制・意味の正しさ・人間の判断は保証できない。ガイドの分だけ返せるレビュー本文の量は減る。提供の自動検証と、AI の分析結果の手動確認を区別する。

[MCP Tools の Structured Content と Output Schema](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) は、サーバーが作る構造化結果と LLM の構造化生成を区別している。outputSchema を AI の最終回答の保証として扱わない。
