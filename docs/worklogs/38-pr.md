## 背景・目的

Steam API のリクエスト変換が FetchReviewsPage の通信手順に埋め込まれていたため、取得条件から API の表現への変換を名前で追え、通信なしで利用できるようにした。

## 変更内容

- 評価種別の all・positive・negative を API の0・1・2へ変換する非公開関数を switch で実装した。
- 名前付きの API 入力型を組み立てる処理と、JSON・クエリを生成する処理を request.go に分離した。
- 公開入力の正規化、通信・期限・応答解析・Body 解放の契約を維持した。
- 責務の説明と Issue #38 単独の検証記録を更新した。

## 検証

既存の送信内容・評価種別・不正入力・HTTP・資源解放を含む関連3パッケージのテストが成功した。振る舞いを維持する Refactor のため、既存テストを変更せず、形式上の Red は作らなかった。

単独ブランチの検査結果と、検査コード・設定が同一のため再利用したフック・実 Go ツールの検証結果は `docs/worklogs/38-steam-request-conversion.md` に記録した。AI のセルフレビューを実施した。人によるレビュー、コード CI、実 Steam の取得と配置は未実施とする。coverage 閾値・分岐・mutation は未導入である。

本書はローカルの PR 本文案であり、push・PR 作成は行っていない。
