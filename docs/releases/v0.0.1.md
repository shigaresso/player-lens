## 変更内容

PlayerLens の開発基盤を保存した。Go 向け AGENTS.md、仕様と ADR の参照手順、Issue 起点の開発、コミット・Issue・PR の形式検査、Lefthook、GitHub Actions を追加した。

Issue・Draft PR の作成に事前検査を組み込み、Release の Draft 作成と公開にも本文・対象 SHA・main の CI・タグの検査を追加した。公開後の本文とタグの対象も照合するようにした。

## 利用方法

この Release のソースアーカイブから規約・scripts・フック・テンプレート・CI を選び、移植先の Issue と PR で導入する。[移植ガイド](https://github.com/shigaresso/player-lens/blob/v0.0.1/docs/reuse.md) に引き継ぐファイルと調整箇所をまとめた。

プロジェクト名・リポジトリ・Issue 番号・仕様書・言語固有の規約を見直し、導入後に共通検査、実フック、実際の Issue・PR の作成と CI を確認する。[開発手順](https://github.com/shigaresso/player-lens/blob/v0.0.1/docs/development.md) と [Release 手順](https://github.com/shigaresso/player-lens/blob/v0.0.1/docs/releases.md) を参照する。

## 依存環境

Python 3.12 以降の標準ライブラリ、Git、curl、tar、install、認証済み gh を使用する。ツール配置は macOS arm64 と Linux x86_64 に対応し、Lefthook 2.1.9 と actionlint 1.7.12 を SHA-256 で検証する。規約ツールの CI は Ubuntu 24.04 と Python 3.12 で実行する。

## 制約

この版は PlayerLens の開発基盤であり、Go アプリケーション・Docker・DB・MCP・Render 配置は未導入である。AGENTS.md のアプリケーション固有の要件は、対象プロジェクトの仕様に合わせて調整する。

日本語の意味、説明と実装の一致、AI の規約遵守は機械的検査だけで保証しない。直接の gh やブラウザ操作を遮断せず、事前検査と書き込みの間の競合も完全には防げない。main の保護設定は現在の private リポジトリの契約では利用できず未設定である。Release の公開でリポジトリの可視性は変わらない。

追加の添付バイナリは配布せず、GitHub のソースアーカイブを利用する。

## 検証

ローカルで `bash scripts/check.sh` の規約ツール100テスト、空白・Lefthook 設定・actionlint・シェル構文の検査を通した。`python3 scripts/verify_hooks.py` の隔離リポジトリでの実フック5テストを通した。外部通信の通常テストは偽 API・偽 gh を使った。

Release の作成・公開 CLI は対象 SHA の push/main の規約 CI と必須ジョブ verify の成功を要求する。実際の PR・main の CI と公開結果は [Issue #5](https://github.com/shigaresso/player-lens/issues/5) に記録する。Go アプリケーションの検査は未導入である。
