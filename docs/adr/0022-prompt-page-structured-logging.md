# ADR-0022：プロンプト作成画面の応答完了を記録する

## 状態と背景

採用。Issue #150 に対応する。ADR-0017・0021 の slog/context・外側からの依存注入と安全な属性の方針を、トップページの HTML 応答へ適用する。ブラウザ内の操作は観測対象に含めない。

## 比較と決定

healthz・MCP のログだけでは、トップページの応答を確認できない。全経路のアクセス middleware は既存のログとの重複や対象範囲が広がるため導入しない。専用 Controller の通常終了時に prompt_page.completed を1回記録する。HTTP 応答処理・クライアント受信・画面操作を区別する。

標準 ServeContent はエラーを戻さないため、既存 page パッケージに応答観測を置く。専用の ResponseWriter を内部で包み、ステータスと最初の書き込み失敗・短い書き込みを結果として返す。標準の本文・Range・条件付き要求は維持し、再送・独自の応答生成は追加しない。Controller から観測結果を handler/logging の固定属性へ渡す。ステータスを常に200とみなしたり、応答 JSON を解析し直したりしない。

logger・時計は run から渡し、生成時には使わない。context をそのまま slog へ渡し、グローバル logger・独自 logger interface・仮の trace ID は追加しない。4xx、5xx、本文書き込み失敗は別の結果として記録する。公開パスは登録とログで共有する。詳細な属性・レベル・原因分類は [公開デモ仕様](../specs/public-demo.md#プロンプト作成画面の応答ログissue-150) に定める。

## 利点と制約

応答の有無・時間・失敗を調べられる。入力・生成文・query・ヘッダー・IP・エラー全文は記録しない。HTML の配信処理が終わったことだけではブラウザの表示・依頼文の生成・MCP 収集の成功を保証しない。

既存 JSON/stderr を使い、ログ writer の通常の失敗で応答を変更しない。保存・保持・転送・任意の writer の非ブロッキングは保証しない。ブラウザからの追加通信・OTel SDK・ファイル保存・新たな goroutine は設けない。panic の既存の伝播を維持し、回復や専用ログを追加しない。

テストは破棄先かメモリ上の記録先を注入し、ターミナルへログを出さない。制御した時計で時間、実 HTTP とプロセス・本番イメージで接続と stderr を確認する。実行結果は [作業記録](../worklogs/150-prompt-page-logging.md) に記録する。
