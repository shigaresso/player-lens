## 背景・目的

Steam の ID・時刻・API 列挙値を組み込み型だけで扱っていたため、値の意味と API との対応、型の違いをコードから追いにくかった。公式の項目名と使用する数値型に基づく定義型を導入し、取得から収集・JSON・CLI・MCP まで引き継いだ。

## 変更内容

- AppID・TimestampCreated・TimestampUpdated を uint32、RecommendationID を uint64 の定義型にした。Review のフィールド名と取得依存・操作・結果・各入口・テストを更新した。
- HTTP adapter の EUserReviewsReviewType・EUserReviewsAppReviewsFilter・EUserReviewsPurchaseType を公式名の int32 型にした。内部の評価種別は EUserReviewsReviewType の列挙値に統一し、文字列の ReviewType と HTTP 内の steamReviewTypeCode を廃止した。all/positive/negative の文字列は入出力境界でのみ解析・生成する。
- 応答専用データから recommendationid を数値に変換し、0・最大値・先頭ゼロを受け付けた。欠落・null・空・不正構文・範囲超過を拒否し、正数条件と重複する正規表現を削除した。
- 収集の重複判定を数値 ID に揃えた。0001 と1は同一とし、最初のレビューと順序を維持した。
- schema_version=1 と既存の外部 JSON 項目名・型を維持し、ID は0・最大値も10進文字列として出力した。先頭ゼロは数値に正規化した。文字列・bool の独自型やアプリの件数制限の型は追加しなかった。
- 仕様・ADR-0012・探索記録と境界の回帰テストを追加・更新した。

## 検証

RecommendationID の型・変換のテストを先に追加し、未実装の型・関数で Red を確認した。変換を実装して同じテストの Green を確認した。次にページ解釈の契約を変更し、未対応の RecommendationID フィールドで Red を確認した。取得・収集・出力を接続し、型変更に必要なテスト参照を更新して関連6パッケージの Green を確認した。

AppID・時刻・列挙値の型の反映は既存動作を維持する Refactor として扱い、形式上の Red は作らなかった。全7パッケージの通常テストが成功した。

ID 変換の原因保持、HTTP を通す数値重複排除、JSON の項目名・型と精度、CLI の HTTP/保存連携、実 SDK を使う MCP の成功・部分失敗のテストを一つずつ追加した。既存実装で Green だったため、実装を変えず回帰テストとして保存した。

`bash scripts/check-app.sh` が成功した。整形・vet・通常テスト7パッケージ、lint（0 issues）、Git 非依存検査、race 付き結合テストを含む全7パッケージ、本番イメージの HTTP・MCP・PORT・シグナル終了・不正設定を確認した。image ID は `sha256:9cfba4fbb8144bd6db8db5d4d87a5a859ba49c176728dc49dc6b322a21aaeab3`。実装と Refactor のコミットで必須フックの規約177テスト・静的検査・ステージ済み Go 整形と commit-msg が成功した。
