# クライアント AI 向けレビュー分析ガイド

## 目的と担当

Issue #35 で、レビューから具体的な設計上の選択とその影響を読み取るための案内を MCP に追加する。分類・要約・比較は接続元の AI、採用・不採用は人間が担当する。Go は共通ガイドの提供と既存の収集・件数・上限だけを担当する。バックエンド LLM、分析結果の受領・検証、レポートの永続保存は導入しない。

## 提供する契約

- `collect_reviews` の結果へ `analysis_guide` オブジェクトを追加する。必須項目は文字列の `version` と `instructions` とし、初版は `version="1"`。ガイドを改訂する場合は版も更新する。
- 正常・空・入力不正・部分失敗・利用制限・応答量超過のすべてのツール結果へ同じガイドを返す。HTTP・未定義ツールなど、ツール結果より前のプロトコルエラーには付与しない。
- ガイドの本文はレビュー本文から組み立てない。`internal/reviewmcp/adapter/handler/protocol/analysis_guide.md` をコンパイル時に埋め込み、実行時ファイル・追加通信・利用回数を必要としない。
- `structuredContent` と同じ JSON テキストへ含め、ツール一覧の出力 schema に宣言する。既存 Collection の schema_version=1、CLI の JSON、入力条件は維持する。トップレベルを厳密に検査する独自クライアントは追加フィールドへの対応が必要となる。
- ガイドも二重化した JSON の128 KiB上限に含める。レビューを省略する場合もガイド・条件・省略件数を保持する。既存のエラー種別、部分結果、利用制限、再試行なしの責務は変えない。

## 分析として案内する内容

- 分類は取得レビューに登場する具体的な評価対象から作り、ジャンルや固定分類を押し付けない。
- 1件の複数意見を分け、おすすめフラグとは別に本文の肯定・否定・両面・不明を読む。
- 同じ対象の似た意見をまとめ、体験・理由・条件を残す。短文や冗談から理由を創作しない。
- 賛否の比較ではソロ・協力、期待する遊び方など、本文にある条件を比べる。異なる側面を対立と扱わず、説明できなければ不明とする。
- レビュー ID を付け、投稿者の意見・未検証の主張と AI の解釈・仮説を区別する。複数作品を比較する場合は作品と条件も対応させる。
- 頻度を記載する場合は同じレビュー ID を同じ意見群で重複計上せず、分母・対象を明示する。件数を重要度や全体の満足率へ置き換えない。
- 空・不足・部分失敗を明示し、取得していない内容で補わない。追加取得の必要性は説明にとどめ、制限や失敗に対して繰り返し呼び出さない。
- 最後に、企画の選択肢ごとに得られる体験・損なわれ得る体験・条件・根拠を示す。人間が採否を決める。

## 保証する範囲

自動検証はガイドの付与、版・本文・schema の対応、JSON の一致、応答量、既存の結果・エラーと通信の維持を対象とする。クライアントの最終回答や意味分類の正確性は検証しない。MCP の outputSchema はサーバーの結果形式を定めるもので、AI の最終回答の schema ではない。

利用手順とコピー用の依頼は `docs/review-analysis.md`、架空データの説明例は `docs/examples/review-analysis.md` に置く。例は実ゲームの評価や、AI を実行した検証結果ではない。実クライアントの確認・未確認は作業記録で別に報告する。

## 期待結果と検証

| 状況 | 期待結果 | 検証 |
| --- | --- | --- |
| 正常・空・エラーのツール結果 | 版1の同じガイドと既存データを返す | 変換のテーブルテストと既存のエラーテスト |
| レビュー本文が外部の操作指示を含む | 本文はデータのままでガイドは変化しない | 変換・実 SDK の呼び出し |
| ガイドを含めると128 KiBを超える | レビューを省略し、条件・ガイド・件数を保持する | 境界値と JSON の実際のシリアライズ量 |
| 対応4版のクライアントが一覧・呼び出しを行う | schema・説明と正常・入力エラーのガイドを受け取る | integration タグの実 SDK クライアント |
| 本番用イメージにソースを共有しない | 埋め込んだガイドを返す | 本番イメージの不正入力呼び出し。実 Steam は使わない |

## 未導入事項

分類結果の提出・集計ツール、意味検証、ランキングの自動取得、データセットの保存、バックエンド LLM、UI は別の判断とする。案内の存在だけで AI の遵守やレポート品質を保証しない。[ADR-0011](../adr/0011-client-review-analysis-guide.md) に選択理由を記録する。
