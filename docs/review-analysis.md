# レビューからゲーム企画の材料を得る

## できること

PlayerLens はレビューと一緒に `analysis_guide`（`version` と `instructions`）を返す。接続元の AI が、何が、どの条件で、なぜ評価されるかを整理し、人間が設計の選択を検討する。

分類はゲームや取得本文から作る。ジャンルや固定の分類数から始めず、おすすめ・非おすすめも本文の意見とは別に読む。最終的な採否は人間に残す。

ガイドは分析の案内であり、AI の最終回答を検査・強制する機能ではない。バックエンドの LLM 呼び出し・API キー、分析結果の提出や保存も必要としない。[仕様](specs/review-analysis.md) と [ADR-0011](adr/0011-client-review-analysis-guide.md) に担当と制約を記載した。

## 依頼の例

[MCP デバッグ手順](mcp-debug.md) に従って登録・起動したうえで、次の文章の App ID を対象作品へ置き換えて依頼する。440 は指定形式の例で、この操作は実 Steam に接続する。

```text
PlayerLens の collect_reviews を使い、app_id=440、language=japanese、
review_type=all、page_size=20、max_reviews=20、max_pages=1 で取得してください。
結果の analysis_guide に沿って、何が、どの条件で、なぜ評価されるかを整理してください。
固定分類やおすすめフラグだけで判断せず、根拠のレビュー ID を付けてください。
投稿者の意見と AI の解釈・不明点を分け、企画の選択肢ごとに
得られる体験・損なわれ得る体験を説明してください。採否は私が判断します。
取得条件・件数・終了理由・不足や偏りも示してください。
追加取得はせず、まず今回の結果だけを分析してください。
```

最初から両評価を確実に含めたい場合は、件数と呼び出し回数を決めて `positive`・`negative` をそれぞれ取得する。例えば各10件・1ページなら合計2回で、MCP と Steam の制限を確認しながら直列で行う。偏りを作った取得なので、得られた比率をゲーム全体の好評率として使わない。`all` でも両評価が必ず入るとは限らない。

複数作品を比べる場合は、対象の App ID と各作品の取得上限を明示し、作品・言語・取得条件を対応させる。比較先を取得していない場合は、その作品の評価を作らせない。

## 追加で深掘りする依頼

```text
追加取得はせず、今の結果のうち「自動化によって楽しみたい役割が失われる」
という解釈を深掘りしてください。
直接そう書かれた意見と、AI が比較から推測した部分を分け、根拠 ID を示してください。
別の説明もあり得るなら挙げ、分からない条件は不明としてください。
改善案を一つに決めず、選択肢ごとの体験の違いを整理してください。
```

これは問いを事前に固定するためではなく、実際に見えた意見の中から気になる点を選ぶ使い方である。

## 結果を読む際の確認

- 作品・取得条件・件数・終了理由と、根拠のレビュー ID が対応しているか。
- 投稿者の意見と AI の解釈が区別され、短文や推測から理由を創作していないか。
- 賛否の違いが、同じ対象の違いなのか、別の機能・遊び方の違いなのか。
- 選択肢によって得られるもの・失われるものが説明され、採用を断定していないか。

エラー・空・省略・偏りがある結果を、完成した調査として扱わない。制限や失敗に対する繰り返しの取得は行わない。Steam は匿名レビュー取得の具体的な回数上限を公表していないため、PlayerLens の毎分6回を守れば Steam 側でも必ず通るとは限らない。[Steam 公式 API](https://partner.steamgames.com/doc/webapi/IUserReviewsService) と [MCP 利用制限](specs/mcp-usage-limits.md) を参照する。

ガイドの提供本文は [analysis_guide.md](../internal/reviewmcp/adapter/handler/analysis_guide.md) を唯一の本体として埋め込む。このページの依頼例はその利用例で、別のガイド本文ではない。ガイドを改訂する際は `analysisGuideVersion`、出力 schema・テスト・本番イメージ検査の期待版を一緒に更新する。

[架空レビューによる分析例](examples/review-analysis.md) で、意見から企画上の選択肢までのつながりを確認できる。
